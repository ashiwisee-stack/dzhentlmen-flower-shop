# Подключение внешних сервисов

Все значения задаются в секретах Worker. На клиент они не передаются. Флажок «настроено» в админке означает наличие параметров, а не успешную проверку доступа к сервису.

## SMS.RU
Задайте SMS_RU_API_ID, SMS_DEV_MODE=0. Отправка использует официальный POST /sms/send; проверяется как общий ответ, так и результат доставки запроса для номера. Ограничены частота запросов, повторная отправка и попытки ввода кода. Код одноразовый, в базе хранится хеш; сессия находится в HttpOnly cookie. Проверьте реальный российский номер после развёртывания. Для другого SMS-провайдера потребуется заменить lib/sms.ts — универсальной совместимости со всеми поставщиками нет.

Официальная документация: https://sms.ru/api/send

## Telegram
Задайте TELEGRAM_BOT_TOKEN и PUBLIC_ORIGIN. В /admin → Настройки создайте ссылку сотрудника: при этом регистрируется webhook /api/telegram/webhook. Откройте ссылку в Telegram и нажмите Start. Для каждого следующего сотрудника создайте новую ссылку. Она одноразовая, действует 10 минут; даёт право получать уведомления магазина, поэтому передаётся только сотруднику.

Покупатель подключается своей кнопкой в кабинете и получает уведомления только о своих заказах. Сначала администратор должен инициализировать webhook. Команда /stop прекращает подписку. Сотрудника можно отключить в админке.

Уведомления пишутся в очередь вместе с заказом или заявкой. Cron отправляет их и повторяет временные ошибки. После неопределённого сетевого ответа возможен повтор уведомления; само оформление заказа от этого не повторяется. Действует лимит автоматических попыток, есть ручной повтор в админке. Отказанные или завершённые возвраты сейчас проверяются кнопкой в заказе.

Документация: https://core.telegram.org/bots/api

## Робокасса
1. Получите логин магазина, Пароль №1 и Пароль №2; для возвратов создайте Пароль №3. Обычный пароль входа в личный кабинет не заменяет эти параметры.
2. В технических настройках магазина выберите SHA256. Result URL: https://ВАШ-ДОМЕН/api/payment/result, метод POST. Success URL и Fail URL: https://ВАШ-ДОМЕН/payment, метод GET. Страница результата проверяет серверный статус; сам переход по ссылке не подтверждает оплату.
3. Заполните ROBOKASSA_LOGIN, ROBOKASSA_PASSWORD1, ROBOKASSA_PASSWORD2, ROBOKASSA_PASSWORD3, ROBOKASSA_TAX и ROBOKASSA_SNO. Налог и систему налогообложения берите из данных продавца. Для предоплаты выбран ROBOKASSA_PAYMENT_METHOD=full_prepayment. Вариант full_payment допустим только когда он соответствует реальному расчёту.
4. Алгоритм ROBOKASSA_HASH_ALGORITHM должен совпадать с кабинетом (сейчас MD5). Для тестового режима налоговые данные и пароль №3 не требуются; чек не отправляется. Сначала ROBOKASSA_ENABLED=1, ROBOKASSA_TEST=1 и тестовые пароли соответствующего режима. Проверьте переход к оплате, Result URL, сумму; состав чека проверяется отдельно при настройке боевой фискализации. Для работы смените на реальные пароли и ROBOKASSA_TEST=0.

Подпись, номер счёта и сумма проверяются сервером. Повторный Result не повторяет оплату. Бонусная скидка распределяется между позициями в копейках; дополнения входят в стоимость букета, доставка — отдельная позиция.

При выдаче оплаченного заказа с предоплатой создаётся задача закрывающего чека, которую обрабатывает Cron через RoboFiscal. Статус доступен в карточке заказа. Настройки фискализации сохраняются в заказе на момент оформления. Эти вызовы подготовлены по документации, но без аккаунта продавца не прошли сквозную проверку.

Возврат — полный, через отдельное подтверждение администратора и Refund API. После запроса нажмите «Проверить возврат»: только подтверждённый результат меняет заказ на «Возврат / Отменён» и возвращает бонусы. При неизвестном результате отправки повторный финансовый запрос блокируется; сверка выполняется в кабинете Робокассы. Частичные возвраты и автоматическое восстановление после отказа провайдера не реализованы. Не исправляйте статус вручную в базе без сверки операции.

Если после возврата ранее начисленные бонусы уже потрачены, баланс может стать отрицательным: это компенсируется будущими начислениями, новые списания недоступны до положительного баланса. Исторические начисления до новой системы журнала требуют отдельной сверки при переносе рабочей базы.

Документация: https://docs.robokassa.ru/ru/pay-interface ; https://docs.robokassa.ru/ru/notifications-and-redirects ; https://docs.robokassa.ru/ru/refund-api ; https://docs.robokassa.ru/ru/second-receipt
